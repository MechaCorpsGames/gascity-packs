# Gas City no-upstream-change feasibility

**Snapshot:** installed `gc` 1.4.0 at `a7297c511d637a3609947386f3389d76ddb2f23b`; Gas City source `1807cf018045e9f225993d97cf6daea37e2ce6e9`; Beads source `abc4a9fa7964d7558f91a06e20404f257e65e264`; and [Memory Beads proposal #5877](https://github.com/gastownhall/beads/issues/5877), 2026-08-24. This is implementation evidence, not a replacement for the architecture.

## Answer

City Life can implement the target contract without changing Gas City for constrained support rows. The no-upstream design requires a City Life-owned Task-project registry, a pinned adapter over observable session-bead metadata, and a connector mediator that reports only delivery outcomes it can prove. Gas City still lacks cleaner public seams for current-Task identity and exact-recipient delivery, which narrows support and motivates upstream improvements without blocking the pack.

Current Beads is also not an executable Memory Beads dependency yet. It still exposes one keyed string plane ([request contract](https://github.com/gastownhall/beads/blob/abc4a9fa7964d7558f91a06e20404f257e65e264/memoryops/memories.go#L5), [map projection](https://github.com/gastownhall/beads/blob/abc4a9fa7964d7558f91a06e20404f257e65e264/memoryops/memories.go#L111)); #5877 explicitly remains a proposal for canonical Memory identity, History, archive/restore, references, guarded writes, and interchange. That is a Beads prerequisite, not a reason to change Gas City.

## Observed facts

### Installed-CLI spikes

The installed CLI matters because it is the surface the pack can actually call. These read-only spikes used an existing local city and projected only structural fields:

- `gc version --long --json` reported 1.4.0 at `a7297c5`, not the checked-out source revision. `gc hook current --help` rendered the parent `gc hook` help and did not list `current`; the command exists at source HEAD but not in the installed binary. Release gates must therefore probe the executable, controller, and Beads tuple rather than infer capability from a checkout.
- `gc session list --json` exposed stable session ID, backing `template`, state, alias, runtime name, provider, and workdir, but no Task route or Project ID. `gc skill list --json` proved visible skill discovery; its own help correctly warns that visibility does not prove materialization.
- An exact city-store `bd -C <city> show <session-id> --json` exposed `currently_processing_bead_id`, `gc.trigger_bead_id`, and `gc.trigger_bead_store_ref`. In the observed demand-created pool session the two IDs agreed and the route was `city`; the selected store's `.beads/identity.toml` supplied its Project ID. Re-reading the selected Task showed it was already closed while the session was drained, so a resolver that also validates live Task ownership would reject the stale tuple as intended. This demonstrates a possible pinned inference, not authoritative Gas City context: the marker can lag live processing and has distinct controller, trigger, and self-claim producers.
- That metadata is not a general contract. Trigger provenance is internal and describes initial demand; named-session assignment may record only `currently_processing_bead_id`, while self-claim uses a separate ID-only lane. It can support a pinned, fail-closed adapter for selected rows, not the generic current-Task claim.
- `gc session submit --json-schema=result` advertised only `submitted`, `queued`, or `interrupted`; `gc session nudge --json-schema=result` advertised `delivered` or `queued` and an optional concrete session ID. `gc nudge status --json-schema=result` exposes queued, in-flight, and dead items, but no durable correlated success receipt after removal. These are acceptance and runtime-injection signals, not proof that the model consumed a message.
- A disposable `gc init` with the installed CLI and installed `bd` failed at their cross-era store boundary. No semantic verdict depends on that failure, but it is direct evidence that City Life must pin and probe the joint executable set. The partial temporary city was not used as product evidence.

- A session record publicly exposes its stable ID, backing `template`, runtime/session names, provider, workdir, timestamps, state, and named-session flag ([wire record](https://github.com/gastownhall/gascity/blob/1807cf018045e9f225993d97cf6daea37e2ce6e9/internal/api/handler_sessions.go#L21)). ### Task, session, and transcript seams

- `gc hook current` returns only the bead most recently self-claimed through `gc hook --claim`, addressed by `GC_SESSION_ID`; it explicitly lacks controller trigger variables in a pool shell ([contract](https://github.com/gastownhall/gascity/blob/1807cf018045e9f225993d97cf6daea37e2ce6e9/cmd/gc/cmd_hook_current.go#L21), [read](https://github.com/gastownhall/gascity/blob/1807cf018045e9f225993d97cf6daea37e2ce6e9/cmd/gc/cmd_hook_current.go#L62)). The self-claim and controller-assigned current bead are separate metadata lanes ([separation](https://github.com/gastownhall/gascity/blob/1807cf018045e9f225993d97cf6daea37e2ce6e9/internal/session/store.go#L191)). The session API's `active_bead` is a cross-rig assignee search, including compatibility aliases, rather than an authoritative task context ([heuristic](https://github.com/gastownhall/gascity/blob/1807cf018045e9f225993d97cf6daea37e2ce6e9/internal/api/handler_sessions.go#L604)). None supplies Task route or expected Project ID.
- Beads can verify a route once City Life already has it: `bd context --json` exposes `project_id` ([context record](https://github.com/gastownhall/beads/blob/abc4a9fa7964d7558f91a06e20404f257e65e264/cmd/bd/context_cmd.go#L14), [population](https://github.com/gastownhall/beads/blob/abc4a9fa7964d7558f91a06e20404f257e65e264/cmd/bd/context_cmd.go#L136)), and explicit command context binds `BEADS_DIR` before opening the target ([binding](https://github.com/gastownhall/beads/blob/abc4a9fa7964d7558f91a06e20404f257e65e264/cmd/bd/main.go#L597)).
- Gas City's session API resolves existing and configured named sessions before accepting a message ([preflight](https://github.com/gastownhall/gascity/blob/1807cf018045e9f225993d97cf6daea37e2ce6e9/internal/api/session_resolution.go#L611)), then returns a request ID and event cursor and emits a correlated success/failure asynchronously ([message handler](https://github.com/gastownhall/gascity/blob/1807cf018045e9f225993d97cf6daea37e2ce6e9/internal/api/huma_handlers_sessions_command.go#L740)). Success means provider submission; submit outcomes distinguish only queued from not queued ([outcome](https://github.com/gastownhall/gascity/blob/1807cf018045e9f225993d97cf6daea37e2ce6e9/internal/session/submit.go#L55)). Structured transcript reads expose normalized messages, provider/logical conversation IDs, exact cursors, and degradation diagnostics ([reader](https://github.com/gastownhall/gascity/blob/1807cf018045e9f225993d97cf6daea37e2ce6e9/internal/api/handler_session_transcript.go#L31), [history envelope](https://github.com/gastownhall/gascity/blob/1807cf018045e9f225993d97cf6daea37e2ce6e9/internal/api/session_structured_types.go#L33)). A correlation nonce observed in target output is therefore stronger receipt evidence than the success event.

### Routing, recovery, and authority

- External-message group resolution computes one target for an explicit handle ([resolution](https://github.com/gastownhall/gascity/blob/1807cf018045e9f225993d97cf6daea37e2ce6e9/internal/extmsg/group_service.go#L348)), but the API accepts the inbound record before starting delivery in a background task ([handler](https://github.com/gastownhall/gascity/blob/1807cf018045e9f225993d97cf6daea37e2ce6e9/internal/api/huma_handlers_extmsg.go#L92)). That task enumerates every transcript member, materializes missing sessions, and nudges each one; explicit targeting only adds a prompt-level self-silencing instruction ([fanout](https://github.com/gastownhall/gascity/blob/1807cf018045e9f225993d97cf6daea37e2ce6e9/internal/api/handler_extmsg.go#L120), [loop](https://github.com/gastownhall/gascity/blob/1807cf018045e9f225993d97cf6daea37e2ce6e9/internal/api/handler_extmsg.go#L183)). Per-recipient failures are logged and are absent from the inbound result.
- Named-session materialization resolves the backing template and immediately builds/creates the session ([materialization](https://github.com/gastownhall/gascity/blob/1807cf018045e9f225993d97cf6daea37e2ce6e9/internal/api/session_resolution.go#L273)); the template resolver does not test effective city, rig, or source-agent suspension ([resolver](https://github.com/gastownhall/gascity/blob/1807cf018045e9f225993d97cf6daea37e2ce6e9/internal/api/session_runtime.go#L311)). Suspension is observable through config/status, but a City Life precheck and later message call have a time-of-check/time-of-use race.
- Gas City exposes no authenticated human principal to a pack command. Event attribution is environment-derived and falls back to the literal `human` ([actor](https://github.com/gastownhall/gascity/blob/1807cf018045e9f225993d97cf6daea37e2ce6e9/cmd/gc/main.go#L1421)). Its signed city-write grants are verify-only, require an external minter, and protect city API mutations rather than pack commands ([grant boundary](https://github.com/gastownhall/gascity/blob/1807cf018045e9f225993d97cf6daea37e2ce6e9/internal/citywriteauth/doc.go#L1), [integration](https://github.com/gastownhall/gascity/blob/1807cf018045e9f225993d97cf6daea37e2ce6e9/internal/citywriteauth/doc.go#L50)).

| Feature | Verdict | Implication |
|---|---|---|
| Citizen binding, opaque route, Project-ID verification | **YES** | City Life can own the binding registry and invoke Beads only after exact route open plus `bd context` verification. |
| BQN resolution for normal commands and launch gates | **YES with constrained support row/pinned upstream evidence** | Support controller-issued `GC_SESSION_ID` + public session/config verification and pre-start `GC_TEMPLATE`. For unmaterialized imported named sessions, require a pack-pinned named-session-to-BQN mapping; the generic public projection is incomplete. Never use `GC_AGENT` or alias as citizen identity. |
| Doctrine and command delivery | **YES** | Use pack commands and an injected fragment on `.template.md` prompts. |
| Skill delivery | **YES with constrained support row/pinned upstream evidence** | Advertise only combinations Gas City actually materializes; command-only rows remain possible elsewhere. |
| Durable association and native-session search | **YES with constrained support row/pinned upstream evidence** | A pre-start pending association plus public session reconciliation can exclude failed launches on tmux/herdr; search only providers whose structured transcript reader is proved. Do not advertise automatic launch capture on runtimes without a proved hook/event path. |
| Current Task and Task-to-Memory references | **YES with constrained support row/pinned upstream evidence** | No public seam returns `(opaque Task route, expected Project ID, Bead ID)`. A lifecycle-specific row can use an explicit launch tuple or infer a unique verified Task from observed context and City Life's complete Task-project registry. |
| Missing/session-suspended named-session wake | **YES with constrained support row/pinned upstream evidence** | Direct session message/submit supports materialization/resume and correlated terminal events. |
| Administrative suspension during wake | **YES as a City Life preflight; no race-free guarantee claimed** | A support row can prove that City Life refuses when immediate preflight observes suspension. Gas City exposes no atomic check-and-materialize contract. |
| Delivery acceptance/injection through direct session API | **YES with constrained support row/pinned upstream evidence** | A synchronous `nudge` result can prove exact-session runtime injection. Queued/submitted proves only acceptance. Observable recipient receipt additionally requires correlated target assistant output or an explicit target acknowledgment after the nonce; a recorded user-input transcript frame is insufficient. |
| Exact recipient routing/receipt through stock external inbound | **NO** | Multi-member conversations fan out and failures are background logs. A one-member DM row is supportable, but it does not prove the shared-room intended-recipient contract. |
| Memory/History/Graph/interchange operations | **YES with constrained support row/pinned upstream evidence** | Feasible without Gas City changes only after a pinned Beads revision actually implements #5877 and its shared dependencies; current Beads is not that revision. |

## Recommended no-upstream architecture

Keep the workaround local behind three deep City Life interfaces so Gas City coupling does not leak through every command:

1. `CitizenContext.Resolve` takes an explicitly selected city and session, reads the public composed config/session projection, and returns the exact backing BQN. It treats `GC_TEMPLATE` only as corroboration and rejects aliases or ambient paths as identity.
2. `CurrentTask.Resolve` supports only producer/lifecycle rows named by the release. An explicit launch-supplied Bead ID and store route is the cleanest row. A pinned session-bead row selects exactly one lane: self-claim when `current_claim_bead_id` is present, otherwise controller assignment from `currently_processing_bead_id`; trigger ID and route may corroborate only when they agree. It reads the exact session snapshot, resolves the selected ID against a complete City Life registry of eligible Task projects, opens every eligible route, requires exactly one match, verifies Project ID, Task kind, live state, and assignment against Gas City's complete accepted identifier set for that session, then rereads the session and requires the relevant state and metadata to be unchanged. An unavailable route, zero or several matches, lane conflict, changed reread, or failed ownership check makes the row indeterminate and the operation fails. A cache may remember a successful route but may not convert an unavailable route into a unique match. This remains a pinned fail-closed inference, not authoritative Gas City context.
3. `Delivery` bypasses stock external inbound fanout. A City Life connector mediator resolves one authenticated connector target to one configured named session and persists an outbox intent and nonce before calling the direct city-scoped session API. It then records the request ID, cursor, and concrete session ID. It reports acceptance, runtime injection, and correlated target assistant output or acknowledgment as separate states. A crash after send but before the result is durably recorded is ambiguous and duplicate-prone because `/submit` has no durable client idempotency key.

This design deliberately leaves unsupported: Task resolution that cannot establish one verified live Task, stock multi-member external inbound, and exactly-once delivery.

The architecture now permits this pinned Task inference, so no further specification change is required for the supported rows.

## If the constraints are unacceptable

1. Ask Gas City for one public, immutable session/launch context record containing source BQN and optional current Task tuple; this removes both imported-named-session ambiguity and Task registry enumeration.
2. Add suspension enforcement inside named-session materialization, not as a City Life preflight.
3. Either make external inbound return correlated per-recipient delivery outcomes and honor a single target, or define the City Life connector row around a separate authenticated mediator that calls the direct session API and proves reply/transcript semantics end to end.
