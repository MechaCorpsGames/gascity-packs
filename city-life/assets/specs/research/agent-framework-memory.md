# Agent-framework memory: OpenClaw and Hermes

**Snapshot:** 2026-08-18. Twenty-five load-bearing claims were checked against source and documentation; all survived adversarial verification.

## Observed

- OpenClaw stores persona and durable knowledge separately. It injects selected memory under explicit per-file and total budgets, while other material remains searchable.
- OpenClaw offers a pre-compaction capture turn and a separate consolidation process. Promoted entries can require source citations; short-lived notes can rank below evergreen entries.
- Hermes separates persona from memory and injects a frozen, roughly 1,300-token memory snapshot at session start. Writes fail on overflow, forcing deliberate consolidation rather than silent loss.
- Both systems scope ordinary operation by agent profile or workspace. That topology is not protection from another process running as the same user.
- Hook coverage and context delivery are framework-specific.

## Implications for City Life

- Gas City's source-agent prompt owns persona; Memory Beads owns durable knowledge. Neither should be reconstructed from the other.
- Startup should carry body-free doctrine and selected references, not the complete Memory corpus. Compact discovery and exact recall remain separate operations.
- Context budgets, truncation, and continuation belong to City Life's retrieval policy. Canonical Memory bodies remain unchanged.
- Pre-compaction and scheduled consolidation are optional capture opportunities. A supported harness/runtime pair must prove the paths it advertises and report unavailable paths honestly.
- Source citations, promotion, decay, and trust ranking are possible consumer policies, not required Memory Beads fields.
