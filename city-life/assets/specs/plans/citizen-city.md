# Citizen memory acceptance

This plan proves the [City Life vision](../vision/city-life-vision.md) against pinned Gas City and Beads revisions with the capabilities and observable metadata required by the [architecture](../architecture/memory.md). It covers the correction, Monday, unfamiliar-rig, citation, identity, and namespace claims without treating provider transcripts as curated Memory.

## Release outcome

The fixture contains Sky, an independently bound control citizen, two rigs, independent Task projects, and one Memory project per citizen. Passing proves only the support rows exercised by the run. Any pack entry point or connector covered by no supported row remains unsupported.

The suite prefers representative high-risk transitions and adversarial controls over exhaustive low-risk permutations. A shared invariant may be proved once at its owning layer; behavior that can vary at a provider or lifecycle seam needs evidence for each advertised support row.

## Phase 0 — dependencies and fixtures

Phase 0 produces reusable pack evidence:

1. Record the pinned dependency revisions and run the City Life capability probes required by the architecture. On each support-row member, observe that a pack command resolves the expected BQN and Memory Project and that City Life's doctrine and skill entry points are available. Missing pack facilities or required upstream capabilities keep the member unsupported. Do not inspect prompts or rerun Gas City persona/skill composition or Beads Memory, History, Graph, interchange, or storage conformance.
2. Verify that the pack-composed roster gives each citizen one distinct, verified Memory project. Missing, ambiguous, conflicting, unreachable, or mismatched bindings fail before a Memory operation.
3. For each supported lifecycle, run City Life's pinned Current-Task adapter against the admitted Gas City context. The result is one Beads-verified live Task and project belonging to the current session; missing, stale, ambiguous, or unverifiable resolution fails before a dependent reference read or mutation.
4. Use a disposable citizen and Memory project to create a sealed corpus with unique labeled targets and body canaries, an unreferenced summary canary, global and rig-relevant records, an archived record, and a multi-page result. Include one full-record fixture with non-empty values in every Memory Beads exact-recall field class applicable to its selected state, including key or aliases, lifecycle or archive provenance, Stored Provenance, and references. Through City Life, prove the documented default and explicit scopes, body-free compact discovery, honest complete traversal without skipped or duplicated matches, and semantic preservation of the full selected record without requiring an opaque upstream wrapper. The summary canary's ID, title, and key remain absent from startup while relevant Task-reference metadata remains allowed. Verdicts use recorded IDs, scopes, provenance, page boundaries, and field-level equality rather than model judgment.
5. Through a supported entry point, create successful city- and rig-scoped conversations for one citizen and a later successful conversation for that citizen, plus a conversation for another citizen and one failed launch. Query the documented scopes. Each applicable successful conversation appears once; the other citizen and failed launch are absent. A provider-deleted transcript leaves the searchable set, while an unreadable present transcript or unsupported reader fails visibly rather than producing a partial success.
6. Populate the support matrix with every advertised member entry point, its observable City Life behavior, and its integration evidence. Unsupported or unclassified entry points remain explicit.

Phase 0 passes when these pack-level outcomes pass; the presence of reviewable artifacts alone is not sufficient.

## Phase A — functional continuity

### Preconditions

- The required dependencies and one support-matrix row are available.
- After the separate Phase 0 retrieval corpus is sealed, Sky and the control citizen each resolve to distinct empty Memory projects.
- Runtime-generated correction, rig-only, transcript-only, and body-canary values are absent from prompts, rigs, transcripts, and existing Memory before the test.

### Correction, Monday, and unfamiliar-rig protocol

1. Start Sky in the first rig and give a correction containing unique correction and body-canary nonces absent from the sealed inputs. Retain the City Life search trace showing no exact nonce match, then the accepted global Memory address and exact stored body. Record a second Memory whose fixture text explicitly names the first rig and assert first-rig relevance.
2. Give a ruling whose fixture text explicitly says it applies in every rig in the city but supplies no relevance option. City Life must record global relevance; a rig tag fails the case.
3. Confirm the Memory writes, then make the originating native conversation unavailable to session search. Both Memories must remain exactly recallable by selected-state address with complete bodies, attribution, and required structured fields.
4. In a separate associated conversation, give the transcript-only nonce while forcing its Memory write to fail before mutation. Sky reports that it was not retained; Memory discovery finds no copy while session search still finds the conversation.
5. From the independently bound control citizen, search for every Sky nonce and assert zero Memory results and no recall attempt.
6. Start Sky in a fresh, non-resumed second-rig conversation. Record the expected backing BQN and the availability of City Life's doctrine and pack skills. Then retain an ordered trace showing compact search, selection of the expected Memory address, exact recall, and only then the nonce-dependent answer. Default second-rig discovery excludes the first-rig Memory; explicit first-rig or all scope returns its expected ID. This observes the assembled pack experience without inspecting prompts or proving Gas City's internal composition.
7. Search session history for the transcript-only nonce. It may inform a session-search answer but must never count as durable Memory.
Phase A passes when fresh Sky conversations resolve the expected BQN and City Life facilities, recover accepted Memory only through selective retrieval, remain isolated from the control citizen, keep transcript-only evidence classified as session history, and exclude startup body canaries from all non-body surfaces. A human may separately record whether Sky's Gas City-defined personality and role feel continuous; that observation is non-gating.

## Phase B — integrity, references, and namespace separation

Phase B is automated and mandatory for release.

### Namespace and resolver attacks

Attempt representative reads and mutations using another citizen's address and ambiguous, stale, mismatched, or unreachable citizen and current-Task context. Each operation remains bound to Penny and the verified current Task or visibly fails before Beads. A refused read returns no protected payload; a refused mutation changes no project or City Life metadata. Verify the actual projects and metadata before and after rather than relying on filtered logs. City Life never falls back to ambient Beads discovery, working directory, aliases, or another citizen.

Body-free inspection of a deliberately shared Task reference is allowed. The reference grants Penny no authority to recall Sky's Memory. The product boundary is `NAMESPACE_ONLY`; same-user shell access is not OS isolation.

### Guarded writes and lifecycle

Send two conflicting updates through City Life from the same starting Memory state. The pack must preserve the semantic distinction between the accepted and conflict outcomes, including any upstream recovery guidance, and must not report silent success or silently lose an accepted write. If an upstream result is unresolved, City Life exposes that distinction rather than inventing a retry or stronger conclusion. A subsequent exact recall records the visible selected state. Any City Life metadata changed by the operation remains consistent with that result or is reported as requiring reconciliation.

For each supported `remember`, `revise`, or rig-relevance field class that accepts user content, seed a valid secret canary and remove it through the owning operation. Prove that current search, reference display, startup guidance, and current-state exact recall no longer return it; archive alone does not pass. Confirm that `doctor` identifies the pack-writable boundary and directs other current-field cleanup to Beads without claiming to detect those secrets. The result and diagnostics make no cleanup claim about retained states, transcripts, exports, replicas, or backups. Active discovery excludes archived Memory by default while explicit recall can still address it, and wrong content is corrected before optional archive.

### Project-qualified Task references

Through City Life, add an unpinned `related` reference from the verified current Task to Sky's Memory, inspect it without target authority, add an exact retained-state pin, and unlink it. The pack preserves the stored target address and pin, keeps the reference body-free and non-blocking, leaves Task readiness and target Memory unchanged, and exposes the upstream outcome distinctions it receives without retargeting. Only recall through Sky's verified citizen binding returns the body.

### Exposure and health

Run the body and unreferenced-summary canaries through every inventoried City Life output class: startup guidance, search, Task/reference display, and recall. Startup excludes the summary canary's identity fields and every body; only recall may return a selected state's complete body, attribution, and required structured fields, search may return only its advertised compact projection, and Task/reference display only permitted reference metadata. Unclassified output paths are unsupported.

Inject representative faults in citizen and Task resolution, Project-ID verification, dependency availability, rig relevance, reference resolution, body exposure, session association, and transcript readability. For each fault, the fixture names the affected feature, expected status or error, and an unaffected control; `doctor` must match them. If City Life stores rig relevance separately, one interrupted update proves that `doctor` reports the inconsistency and that the supported reconciliation path restores a result consistent with the accepted Memory state.

Phase B passes when namespace attacks cannot redirect pack reads or writes, upstream write conflicts remain visible, references preserve their meaning through the pack, City Life surfaces honor their body classifications, and each injected fault is reported honestly.
